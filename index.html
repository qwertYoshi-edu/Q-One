      Q-ONE / TRANSPARENCY

      データと利用上の注意

      1. データの保存場所

      問題パック、解答履歴、復習スケジュール、学習設定などは、利用中のブラウザーの IndexedDB に保存されます。アプリの運営者が管理する学習データ用サーバーには保存されません。保存データはこのブラウザー・端末・公開元の組み合わせに依存し、暗号化された保管領域であることを保証するものではありません。

      2. アカウント・クラウド同期

      Q-Oneにはアカウント登録、ログイン、クラウド同期機能はありません。別の端末やブラウザーへ自動で学習データは引き継がれません。ブラウザーのサイトデータ削除、プライベートブラウズ終了、端末の初期化、ストレージ容量の都合などでデータが失われる可能性があります。

      3. 外部通信と問題データの送信

      画面表示・動画/QR関連機能のため、次の第三者ライブラリを jsDelivr CDN から読み込みます。

      • qrcode-generator 2.0.4
      • mp4-muxer 5.2.2
      • MP4Box.js 0.5.3
      • jsQR 1.4.0（QR解析用Web Workerから読み込み）

      CDNへのアクセスでは、接続先にIPアドレス、ブラウザー情報、要求されたライブラリの情報などが伝わる場合があります。確認したQ-Oneのソースコードには、問題文・正解・解答履歴を外部へ送るための fetch / XMLHttpRequest / WebSocket / sendBeacon は実装されていません。問題の解析・動画処理はブラウザー内で行います。ただし、第三者ライブラリの配布元やブラウザー・拡張機能などの挙動まで保証するものではありません。

      4. バックアップと復元

      設定画面からJSONバックアップを定期的にエクスポートし、端末外の安全な場所へ保管してください。バックアップには問題文、正解、学習履歴などが含まれることがあります。他人に渡したり、公開場所へアップロードしたりしないでください。インポートは現在の保存データ全体を置き換えます。出所が不明なJSONを読み込まず、復元前に必要なバックアップを別途保管してください。

      5. オフライン利用

      この配布版にはService Workerによるアプリ本体・ライブラリのオフラインキャッシュがありません。外部CDNからのライブラリ読み込みが必要なため、オフラインで全機能を利用できるとは案内していません。ネットワークがない場合、一部機能または初回起動が動作しない可能性があります。

      6. 問題の正確性・著作権

      生成AIなどを利用して作成した問題・解説・正解は、誤り、古い情報、曖昧な表現を含む可能性があります。Q-Oneは内容の正確性を保証しません。教科書・辞書・信頼できる資料などで確認してから学習に使ってください。他者が作成した問題文、画像、音声、動画を取り込む場合は、著作権・利用規約・ライセンスを確認し、必要な許諾や出典表示を行ってください。

      7. 復習提案の計算方法

      Q-Oneは正式なFSRSではなく、説明可能性を優先した独自の簡易間隔反復方式を使います。初回の基準間隔は Again＝10分、Hard＝1日、Good＝3日、Easy＝7日です。2回目以降のAgainは前回間隔×0.25（10分以上・1日以下）、Hard/Good/Easyは前回間隔×1.2/2.0/2.8×難易度係数です。難易度係数は 1.1 −（難易度 − 1）×0.02 で、難易度は1〜10の範囲で評価に応じて変化します。Againは難易度を上げ、Hardは少し上げ、Good/Easyは下げます。Again以外の間隔は1日以上・最大3650日です。

      この計算は学習履歴に基づく提案であり、記憶保持率や学習成績を予測・保証するものではありません。「定着済み」は、累計評価3回以上、現在の間隔7日以上、直近3回がGoodまたはEasyというアプリ内の判定条件です。学習効果を確かめるには、利用者を対象とした別途の実験が必要です。

      8. 第三者ライブラリとライセンス

      各ライブラリの著作権表示・ライセンス本文・参照先は、配布物の THIRD_PARTY_LICENSES.md に記載しています。mp4-muxer は npm 上で非推奨（deprecated）とされ、後継ライブラリへの移行が案内されています。現行処理との互換性を保つため本版では利用を継続していますが、今後の保守・更新が行われない可能性があります。バージョン固定やライセンス確認は安全性の保証ではありません。

      最終確認日：2026-11-09。更新時には依存関係・通信処理・ライセンスを再確認してください。

      問題の作り方ガイド

      3つの基本ルール

      1. 基本の形: [種類] 問題文 @ 答え で書く
      2. 重要度: 問題の後に _3 のように付ける (任意)
      3. 区切り: 各問題の末尾に # を付ける

      記号の役割

      記号役割
      []問題の種類を指定（check, select など）
      @問題と答えの区切り
      {}選択問題の正解
      <>選択問題の不正解 / 穴埋めの空欄
      #問題の終わり
      _重要度を指定（_1 低 〜 _3 高）

      コピーして試そう

      以下の形式例をコピーして、例題を試すことができます。

      [check]apple@りんご_3# [select]日本の首都は？@{東京}<大阪><京都>_3# [enter]1+1=?@2_1# [fill]犬も歩けば@<棒>にあたる_2#
